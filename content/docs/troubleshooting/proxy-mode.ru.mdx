Внутренний сервер в режиме прокси получает скины от прокси. Это не то же самое, что доступ к Java API для плагинов на этом сервере.

## Обычные скины через прокси [#ordinary-proxy-managed-skins]

Установите SkinsRestorer на прокси и на каждый внутренний сервер. Настройте перенаправление профилей. На каждом внутреннем сервере оставьте `server.proxyMode.detection` равным `AUTO`.

MySQL или PostgreSQL не нужны только потому, что у вас несколько внутренних серверов. Прокси может хранить данные в файлах и передавать скины как обычно.

Если плагины на внутренних серверах не вызывают API, доступ к API на них можно отключить:

```yaml title="config.yml внутреннего сервера (фрагмент SkinsRestorer)"
server:
  proxyMode:
    detection: AUTO
    api: false
```

Перезапустите внутренний сервер и выполните [проверку перехода между серверами](/docs/installation/quick-start).

## Плагину на внутреннем сервере нужен API [#a-backend-plugin-needs-the-api]

Оставьте `server.proxyMode.api: true`, это значение по умолчанию. Подключите прокси и каждый внутренний сервер с включённым API к одной базе MySQL или PostgreSQL с одинаковым префиксом таблиц.

Файловое хранилище не поддерживает этот режим API. Провайдер API может оставаться недоступным, даже если обычные скины через прокси работают.

Следуйте [руководству по API на внутреннем сервере](/docs/development/proxy-api), затем проверьте логи инициализации базы данных.

## Автоматическое определение не работает [#automatic-detection-fails]

Сначала исправьте настройки перенаправления на платформе. Если определение всё равно не срабатывает на известном внутреннем сервере за прокси, задайте там `server.proxyMode.detection: ENABLED` и перезапустите сервер.

Используйте `DISABLED` только на отдельном сервере или на внутреннем сервере, который должен сам управлять своими скинами. Внутренний сервер в отдельном режиме может конфликтовать с прокси при смене скинов.

## Где запускать диагностику [#where-to-run-diagnostics]

Внутренние серверы в режиме прокси поддерживают `/sr status` и `/sr dump` для локальной диагностики. Управление хранилищем и обычные команды скинов выполняйте на прокси.

Настройка перенаправления описана в руководствах для [Velocity](/docs/installation/velocity) и [BungeeCord](/docs/installation/bungeecord). Устройство системы описано в разделе [роль прокси](/docs/concepts/proxy).
