## Нужен ли offline mode? [#do-i-need-offline-mode]

Нет. SkinsRestorer работает с online и offline аутентификацией. Оставьте свою политику аутентификации. У внутреннего сервера за прокси свои требования к перенаправлению данных игроков.

## Нужна ли база данных для сети серверов? [#do-i-need-a-database-for-a-network]

Обычным скинам, которыми управляет прокси, SQL не нужен. Плагину, который использует API на внутреннем сервере в режиме прокси, нужно общее хранилище MySQL или PostgreSQL.

Прежде чем менять хранилище, прочитайте раздел [режим прокси](/docs/troubleshooting/proxy-mode).

## Почему после clear не всегда виден Стив? [#why-does-clear-not-always-show-steve]

`/skin clear` удаляет сохранённый выбор. Дальнейший результат зависит от скина аккаунта и правил скинов по умолчанию.

## Почему скин по URL не меняется после правки изображения? [#why-does-the-url-image-not-change-after-i-edit-it]

Скин, созданный по URL, хранится как подписанная текстура в кеше. Загрузите исправленный PNG и выберите новый результат. `/skin update` обновляет только данные скина аккаунта.

## Можно ли использовать своё изображение плаща? [#can-i-use-a-custom-cape-image]

Сайт поддерживает выбор из существующих плащей при создании скина. Он не принимает произвольные PNG плащей и не передаёт право владения плащом аккаунту.

Прочитайте раздел [плащи](/docs/features/capes).

## Значит ли успешный статус, что все сервисы работают? [#does-a-green-status-mean-all-services-work]

Нет. `/sr status` проверяет сервисы UUID и профилей аккаунтов. MineSkin, загрузку через сайт, рекомендации и доступ к базе данных нужно проверять отдельно.

## Где полный справочник? [#where-is-the-full-reference]

Отправьте описание конфигурации, точную команду, полный текст ошибки, диагностический отчёт и свежий лог. Используйте [список для поддержки](/docs/troubleshooting/debugging).
