`<argument>` es obligatorio. `[argument]` es opcional. `a|b` indica alias. `/skinsrestorer` es un alias de `/sr`. Pon entre comillas los nombres de skin, las entradas de skin o las URL que contengan espacios.

En la consola, escribe los comandos sin la barra inicial. Los comandos sin `<selector>` actúan sobre quien los ejecuta, así que solo funcionan en el juego. Las formas cortas `/skin <skinName> <selector>` y `/skull <skinName> <selector>` también funcionan solo en el juego. Desde la consola, usa `/skin set` o `/skull get`. `/sr purgeolddata` solo funciona en la consola. El modo proxy cambia qué comandos registra un servidor.

## Permisos especiales [#special-permissions]

| Permiso | Uso |
| --- | --- |
| `skinsrestorer.player` | Grupo de jugador incluido: comandos sobre uno mismo y el menú. Todos los jugadores lo tienen de forma predeterminada. |
| `skinsrestorer.command.*` | Otra forma de dar el grupo de jugador incluido |
| `skinsrestorer.admin` | Grupo de administrador incluido: contiene el grupo de jugador y las acciones sobre otros jugadores |
| `skinsrestorer.admincommand.*` | Otra forma de dar el grupo de administrador incluido |
| `skinsrestorer.bypasscooldown` | Ignora los tiempos de espera de los comandos |
| `skinsrestorer.bypassdisabled` | Ignora los nombres de skin bloqueados |
| `skinsrestorer.ownskin` | Permite elegir el nombre de tu propia cuenta cuando los permisos por skin están activados |
| `skinsrestorer.skin.<name>` | Permite elegir una skin concreta |

El grupo de administrador incluido no contiene `reload`, `dump` ni `purgeolddata`. Ningún grupo incluido contiene `skinsrestorer.command.skull` ni `skinsrestorer.ownskin`. Da estos nodos de forma explícita cuando los necesites. `skinsrestorer.command.skull` solo controla `/skull` y `/skull help`.

SkinsRestorer trata los dos nodos comodín como nombres de grupo. Un plugin de permisos que expande los comodines por su cuenta puede dar más permisos. Por ejemplo, puede tratar `skinsrestorer.command.*` como si diera `skinsrestorer.command.set.other`.

Usa [acceso de jugadores](/docs/configuration/player-access) para configurar los grupos. Usa [restricciones de skins](/docs/configuration/restrict-skins) para los nombres bloqueados, los prefijos de URL, el acceso por skin y el consentimiento obligatorio.

## Selectores de objetivo y acciones de administración [#target-selectors-and-administrative-behavior]

Un `<selector>` acepta uno o varios objetivos:

- El nombre de un jugador conectado. Una coincidencia exacta tiene prioridad sobre una que no distingue mayúsculas y minúsculas.
- El UUID de un jugador.
- `-all` para todos los jugadores conectados.
- `-random` para un jugador conectado al azar.

Une varios objetivos con `+`, por ejemplo `/sr applyskin Steve+Alex`.

`/skin set <skinName> <selector>` cambia la selección guardada del objetivo. `/sr applyskin <selector>` vuelve a aplicar la skin que corresponde al objetivo.

`/skin notification ignore-cracked-client` oculta el aviso para clientes en modo offline. El comando solo está disponible mientras el jugador no haya ocultado el aviso.

`/sr createcustom` guarda una skin con nombre. `/sr setcustomname` cambia el nombre que se muestra y usa el mismo permiso. `drop` y `purgeolddata` borran datos guardados, así que [haz una copia de seguridad antes](/docs/configuration/backups).

`/skin favourite` añade o quita la selección actual de favoritos. `history` usa el permiso `undo`. `search`, `edit` y `upload` dan enlaces para el navegador; no guardan por sí mismos una imagen editada.

`/sr status` comprueba los servicios de cuentas. `/sr dump` sube un informe de diagnóstico. Lee [recopilar diagnósticos](/docs/troubleshooting/debugging) para saber qué incluye cada uno.

## Modo proxy [#proxy-mode]

Ejecuta los comandos de jugador y la administración del almacenamiento a través del proxy. En modo proxy, un backend solo registra `/sr`, `/sr help [query]`, `/sr status` y `/sr dump`. No registra `/skin`, `/skins`, `/skull` ni los demás comandos `/sr`.

## Tiempos de espera [#cooldowns]

Los cambios de skin y las peticiones de cabezas tienen cada uno un tiempo de espera predeterminado de 30 segundos. Tras un error, el tiempo de espera predeterminado es de 5 segundos. `skinsrestorer.bypasscooldown` ignora estos tiempos de espera.

Usa la [configuración de comandos](/docs/reference/commands) para cambiar las duraciones.
