`<argument>` is required. `[argument]` is optional. `a|b` lists aliases. `/skinsrestorer` is an alias of `/sr`. Put quotation marks around a skin name, skin input, or URL that contains spaces.

In the console, omit the leading slash. Commands without a `<selector>` act on the sender, so they work only in game. The short forms `/skin <skinName> <selector>` and `/skull <skinName> <selector>` also work only in game. From the console, use `/skin set` or `/skull get` instead. `/sr purgeolddata` works only in the console. Proxy mode changes which commands a server registers.

## Special permissions

| Permission | Purpose |
| --- | --- |
| `skinsrestorer.player` | Built-in player group: self-service commands and the menu. Every player has it by default. |
| `skinsrestorer.command.*` | Alternate grant for the built-in player group |
| `skinsrestorer.admin` | Built-in admin group, including the player group and other-player operations |
| `skinsrestorer.admincommand.*` | Alternate grant for the built-in admin group |
| `skinsrestorer.bypasscooldown` | Bypass command cooldowns |
| `skinsrestorer.bypassdisabled` | Bypass blocked skin names |
| `skinsrestorer.ownskin` | Select your own account name with per-skin permissions enabled |
| `skinsrestorer.skin.<name>` | Select an individual permitted skin |

The built-in admin group omits `reload`, `dump`, and `purgeolddata`. No built-in group includes `skinsrestorer.command.skull` or `skinsrestorer.ownskin`. Grant these nodes explicitly when needed. `skinsrestorer.command.skull` controls only `/skull` and `/skull help`.

SkinsRestorer reads the two wildcard nodes as group names. A permission plugin that expands wildcards itself can grant more. For example, it can treat `skinsrestorer.command.*` as a grant for `skinsrestorer.command.set.other`.

Use [player access](/docs/configuration/player-access) to configure groups. Use [skin restrictions](/docs/configuration/restrict-skins) for blocked names, URL prefixes, per-skin access, and required consent.

## Target selectors and administrative behavior

A `<selector>` accepts one or more targets:

- An online player name. An exact match wins over a case-insensitive match.
- A player UUID.
- `-all` for every online player.
- `-random` for one random online player.

Join several targets with `+`, for example `/sr applyskin Steve+Alex`.

`/skin set <skinName> <selector>` changes a target's saved selection. `/sr applyskin <selector>` reapplies the skin resolved for the target.

`/skin notification ignore-cracked-client` dismisses the warning for offline-mode clients. The command is available only while the player has not dismissed the warning.

`/sr createcustom` stores a named skin. `/sr setcustomname` changes its display label and uses the same permission. `drop` and `purgeolddata` remove stored data, so [back up first](/docs/configuration/backups).

`/skin favourite` toggles the current selection in favorites. `history` uses the `undo` permission. `search`, `edit`, and `upload` provide browser links rather than saving an edited image themselves.

`/sr status` checks account services. `/sr dump` uploads a diagnostic report. Read [diagnostic collection](/docs/troubleshooting/debugging) for what each includes.

## Proxy mode

Run player commands and storage administration through the proxy. In proxy mode, a backend registers only `/sr`, `/sr help [query]`, `/sr status`, and `/sr dump`. It does not register `/skin`, `/skins`, `/skull`, or the other `/sr` commands.

## Cooldowns

Skin changes and skull requests each use a 30-second cooldown by default. Their error cooldowns default to 5 seconds. `skinsrestorer.bypasscooldown` bypasses these cooldowns.

Use [command configuration](/docs/reference/commands) to change the durations.
