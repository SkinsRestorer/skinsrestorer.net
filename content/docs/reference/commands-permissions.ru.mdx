`<argument>` обязателен. `[argument]` необязателен. `a|b` перечисляет псевдонимы. `/skinsrestorer` является псевдонимом `/sr`. Если имя скина, данные скина или URL содержат пробелы, заключите их в кавычки.

В консоли команды вводятся без начального слеша. Команды без `<selector>` действуют на отправителя, поэтому работают только в игре. Короткие формы `/skin <skinName> <selector>` и `/skull <skinName> <selector>` тоже работают только в игре. В консоли вместо них используйте `/skin set` или `/skull get`. `/sr purgeolddata` работает только в консоли. От режима прокси зависит, какие команды регистрирует сервер.

## Особые разрешения [#special-permissions]

| Разрешение | Назначение |
| --- | --- |
| `skinsrestorer.player` | Встроенная группа игрока: команды для себя и меню. По умолчанию она есть у каждого игрока. |
| `skinsrestorer.command.*` | Альтернативный способ выдать встроенную группу игрока |
| `skinsrestorer.admin` | Встроенная группа администратора: группа игрока и действия над другими игроками |
| `skinsrestorer.admincommand.*` | Альтернативный способ выдать встроенную группу администратора |
| `skinsrestorer.bypasscooldown` | Обход задержки между командами |
| `skinsrestorer.bypassdisabled` | Обход запрещённых имён скинов |
| `skinsrestorer.ownskin` | Выбор имени своего аккаунта, когда включены разрешения на отдельные скины |
| `skinsrestorer.skin.<name>` | Выбор отдельного разрешённого скина |

Встроенная группа администратора не включает `reload`, `dump` и `purgeolddata`. Ни одна встроенная группа не включает `skinsrestorer.command.skull` и `skinsrestorer.ownskin`. При необходимости выдайте эти разрешения явно. `skinsrestorer.command.skull` управляет только `/skull` и `/skull help`.

SkinsRestorer читает два разрешения с `*` как имена групп. Плагин разрешений, который сам раскрывает `*`, может выдать больше. Например, он может считать, что `skinsrestorer.command.*` выдаёт и `skinsrestorer.command.set.other`.

Группы настраиваются в разделе [доступ игроков](/docs/configuration/player-access). Запрещённые имена, префиксы URL, доступ к отдельным скинам и обязательное согласие описаны в разделе [ограничение скинов](/docs/configuration/restrict-skins).

## Селекторы целей и действия администратора [#target-selectors-and-administrative-behavior]

`<selector>` принимает одну или несколько целей:

- Имя игрока в сети. Точное совпадение важнее совпадения без учёта регистра.
- UUID игрока.
- `-all` для всех игроков в сети.
- `-random` для одного случайного игрока в сети.

Несколько целей соединяйте через `+`, например `/sr applyskin Steve+Alex`.

`/skin set <skinName> <selector>` меняет сохранённый выбор цели. `/sr applyskin <selector>` повторно применяет скин, определённый для цели.

`/skin notification ignore-cracked-client` скрывает предупреждение для клиентов в offline mode. Команда доступна, только пока игрок не скрыл предупреждение.

`/sr createcustom` сохраняет именованный скин. `/sr setcustomname` меняет его отображаемое имя и использует то же разрешение. `drop` и `purgeolddata` удаляют сохранённые данные, поэтому [сначала сделайте резервную копию](/docs/configuration/backups).

`/skin favourite` добавляет текущий скин в избранное или убирает его оттуда. `history` использует разрешение `undo`. `search`, `edit` и `upload` дают ссылки на сайт и сами не сохраняют изменённое изображение.

`/sr status` проверяет сервисы аккаунтов. `/sr dump` загружает диагностический отчёт. Что входит в каждый из них, описано в разделе [сбор диагностики](/docs/troubleshooting/debugging).

## Режим прокси [#proxy-mode]

Команды игроков и управление хранилищем выполняйте через прокси. В режиме прокси внутренний сервер регистрирует только `/sr`, `/sr help [query]`, `/sr status` и `/sr dump`. Он не регистрирует `/skin`, `/skins`, `/skull` и другие команды `/sr`.

## Задержки [#cooldowns]

По умолчанию смена скина и запрос головы имеют задержку 30 секунд. Задержка после ошибки по умолчанию 5 секунд. `skinsrestorer.bypasscooldown` позволяет обходить эти задержки.

Длительность меняется в [настройках команд](/docs/reference/commands).
