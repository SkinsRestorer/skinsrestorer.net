Это руководство описывает Velocity с внутренними серверами Paper. Для внутреннего сервера с модами настройте поддержку перенаправления по [руководству по совместимости Velocity](https://docs.papermc.io/velocity/server-compatibility/).

## Перед началом [#before-you-start]

Нужен доступ к прокси и ко всем внутренним серверам. Игроки должны подключаться только через прокси. Порты внутренних серверов должны принимать подключения только из доверенных источников.

Режим modern требует совместимых версий Minecraft и внутренних серверов. Прежде чем выбрать другой режим, прочитайте [официальную инструкцию по перенаправлению](https://docs.papermc.io/velocity/player-information-forwarding/).

## Настройка перенаправления modern [#configure-modern-forwarding]

1. Остановите прокси и внутренние серверы.
2. В `velocity.toml` задайте `player-info-forwarding-mode` равным `modern`.
3. Откройте файл `forwarding.secret` на прокси.
4. Укажите этот же секрет на каждом внутреннем сервере Paper.

```toml title="velocity.toml (фрагмент)"
player-info-forwarding-mode = "modern"
```

```properties title="server.properties внутреннего сервера (фрагмент)"
online-mode=false
```

```yaml title="config/paper-global.yml внутреннего сервера (фрагмент для Paper 1.19+)"
proxies:
  velocity:
    enabled: true
    online-mode: true
    secret: "YOUR_FORWARDING_SECRET"
```

Задайте `proxies.velocity.online-mode` таким же, как `online-mode` на прокси. Значение `true` в примере подходит для прокси с аутентификацией. Для режима modern оставьте `settings.bungeecord` в `spigot.yml` выключенным.

Paper 1.18.2 и более ранние версии используют `settings.velocity-support` в `paper.yml`. Для этих версий следуйте руководству платформы.

## Установка SkinsRestorer [#install-skinsrestorer]

1. Положите `SkinsRestorer.jar` в папку `plugins` прокси.
2. Положите тот же релиз в папку `plugins` каждого внутреннего сервера Bukkit.
3. Запустите внутренние серверы и прокси.
4. Проверьте все логи запуска на ошибки перенаправления и SkinsRestorer.

Для внутренних серверов Fabric или NeoForge вместо этого установите соответствующий JAR мода и мод для перенаправления. Прочитайте руководство для [Fabric](/docs/installation/fabric) или [NeoForge](/docs/installation/neoforge).

На внутренних серверах оставьте `server.proxyMode.detection: AUTO`, если определение работает. При правильном перенаправлении SkinsRestorer обычно сам обнаруживает прокси.

## Проверка [#check]

Выполните [первую проверку скина и переход между серверами](/docs/installation/quick-start). Команды скинов используют разрешения прокси, поэтому выдавайте доступ на прокси.

Стандартного файлового хранилища достаточно для обычных скинов, которыми управляет прокси. Плагину на внутреннем сервере, который вызывает API, нужно [общее хранилище MySQL или PostgreSQL](/docs/configuration/database). Настройка API описана в [руководстве по API на прокси](/docs/development/proxy-api).

## Если не работает [#if-it-fails]

Неверный секрет перенаправления вызывает ошибку подключения. Исправьте её до изменения настроек скинов. Если внутренний сервер предупреждает о режиме или команды работают только на одном сервере, откройте [решение проблем с прокси](/docs/troubleshooting/proxy-mode).
