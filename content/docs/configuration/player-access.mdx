Configure permissions on the platform that owns the command. On a proxy network, ordinary skin commands run through the proxy.

## Default player access

Every player can use the normal player commands by default. You do not need to grant anything. These commands include `/skin set`, `/skin url`, `/skin upload`, `/skin clear`, `/skin undo`, `/skin history`, `/skin random`, `/skin update`, `/skin search`, `/skin edit`, the favorites commands, and the `/skins` menu.

The `skinsrestorer.player` permission groups these commands. Commands that act on other players, `/skull`, and `/sr` are not in this group.

## Remove a command from players

Deny the node of that command in your permission plugin. Find the nodes in the [command reference](/docs/reference/commands-permissions). For example, this LuckPerms command blocks URL skins for the default group:

```text
/lp group default permission set skinsrestorer.command.set.url false
```

On a Velocity proxy, LuckPerms uses `/lpv` instead of `/lp`. On BungeeCord, it uses `/lpb`.

This also blocks `/skin upload`, because it uses the same node.

To block all player commands on Paper or Spigot, deny `skinsrestorer.player`. Velocity, Fabric, and NeoForge ignore a denied `skinsrestorer.player`. On these platforms, deny each command node.

### BungeeCord

BungeeCord cannot tell SkinsRestorer that a permission is denied. With the default `commands.forceDefaultPermissions: true`, every player keeps all player commands, even after a denial.

To control player commands on BungeeCord:

1. Set `commands.forceDefaultPermissions: false` in the proxy's `config.yml`.
2. Restart the proxy.
3. Grant each command node that players need, such as `skinsrestorer.command` and `skinsrestorer.command.set`.

Players then lose every node that you do not grant. Granting `skinsrestorer.player` alone is not enough on BungeeCord.

## Grant staff commands

Grant only the nodes needed for the staff task. `skinsrestorer.admin` includes player commands, other-player operations, and several administrative actions. On Paper and Spigot, server operators get `skinsrestorer.admin` by default.

The built-in admin group does **not** include `skinsrestorer.admincommand.reload` or `skinsrestorer.admincommand.dump`. Grant them explicitly if staff need `/sr reload` or `/sr dump`. `/sr purgeolddata` works only from the console. A permission plugin's wildcard behavior can differ from SkinsRestorer's groups.

## Check

1. Join with a regular player account.
2. Run `/skin set xknat`.
3. Try a command that you denied, and a staff-only command.
4. Check the permission manager's effective permissions if results differ.

Do not use an operator account as the only permission check. For denied commands, use [permission troubleshooting](/docs/troubleshooting/permissions).
