The [Skin Studio](/studio) works with Java Edition skins in your browser. It has three parts:

- **Library** on the left: the skins that this browser keeps.
- The selected skin in the center, as a 3D model that you can turn.
- Options on the right: the model, the cape, and the command to generate. They appear once you select a skin.

On a phone, the library opens from the **Library** button, and the options are below the model.

The [Upload](/upload) and [Generator](/generator) pages open the same Skin Studio. **Upload** always makes a `/skin url` command. **Generator** always makes a `/sr createcustom` command.

On the [Skin Studio](/studio) page, choose **Use on a server** or **Custom skin**. The line under the choice explains the command:

- `/skin url` sets the skin on the player who runs it.
- `/sr createcustom` saves the skin on the server under a name. Players can then use that name with `/skin set`.

The Studio does not connect to your Minecraft server. For details, read [Privacy](#privacy).

## Add a skin

Select **+** in the library, then choose one of these:

- **Upload PNG**: a skin PNG up to 5 MB. You can also drop PNG files on the center of the page.
- **Create skin**: a plain classic or slim figure that you paint and save.
- **Open .skin file**: a SkinsRestorer storage file, such as `.customskin`. The Studio reads the texture URL in the file and opens that texture. If the file cannot be used, the Studio shows **This skin file could not be opened** with the reason. On the [Generator](/generator) page, **Open .skin file** also shows in the center when no skin is selected.
- **Open texture URL**: a texture hash or a `https://textures.minecraft.net/texture/…` URL.

When the library is empty, it also shows **Upload PNG** and **Create skin** buttons. The Studio adds each new skin to the library and selects it. If the same skin with the same model is already in the library, the Studio uses that skin. A selected skin shows at once, and nothing is uploaded.

The Studio accepts texture links only from `textures.minecraft.net`. For a skin from another site, download the PNG and upload it. The Studio does not look up player names.

## Browse the gallery [#gallery]

Select **Gallery** beside **Library**, or select **Browse gallery** from the empty view. Search by name, then select a skin to preview it. If no skin matches, select **Clear search** to see all skins again.

The gallery uses the [official recommended skins](https://github.com/SkinsRestorer/cool-skins). A normal visit does not select a skin automatically. The page address keeps the gallery skin and your search. The browser Back and Forward buttons go between the gallery skins that you selected.

To use the gallery with the keyboard, press `Tab` to move the focus to the skin grid. The grid is one `Tab` stop. Use the arrow keys, `Home`, and `End` to move between skins. Press `Enter` or `Space` to select a skin.

Browsing and selecting gallery skins do not add them to your library. Select **Save to library** below the model to keep a copy. You can also select **Edit skin** and then **Save to library** to keep an edited copy. The gallery original stays unchanged. The current command, model, cape, and advanced options work as usual.

Select **Copy gallery link** to share the original gallery skin. The link opens that public entry in Studio. Links from Upload and Generator keep the command type fixed. Your library and private edits are not included. **Download PNG** downloads the selected skin without generating a command.

## Get a command

Select a skin, check the model and the cape, then select the generate button. Uploading can take up to a minute. If you do not want to wait, select **Stop waiting** below the button.

When the command is ready, the Studio shows **Your command is ready** with the command and a copy button. The generate button then shows **Command ready**. It stays off until you change the skin or an option.

If the upload fails, the Studio keeps your choices and tells you what to check before you try again. Read [upload problems](/docs/troubleshooting/uploads) for each failure. The [upload guide](/docs/features/skin-upload) and [custom skins](/docs/configuration/custom-skins) explain each command.

## Edit a skin [#edit-a-skin]

Select **Edit skin** below the model to paint or fix the selected skin. Read [Paint and fix a skin in the Skin Studio](/docs/features/skin-painting) for the tools, layers, shortcuts, and the skin check.

## Save your work

- **Save changes** writes your changes to the skin in the library. The skin keeps its original file, so you can revert to it later.
- **Save as copy** adds a new skin with your changes and selects it. The skin that you opened does not change.
- **Cancel** returns to the skin that was selected before.

For a new skin from **Create skin**, **Save to library** adds it to the library.

The model, cape, upload method, API key, and skin name stay as you set them while you edit, save, or cancel.

An icon next to the name shows the save state. Point at the icon to see it:

| Icon | State |
| --- | --- |
| Check mark | Saved in the library. |
| Dot | Unsaved changes, or a new skin that is not saved yet. |
| Spinner | Saving. |
| Crossed-out disk | The browser cannot save this skin. |

If you edit the same skin in two tabs and save in one tab first, the other tab does not overwrite it. It asks you to save your work as a copy or to replace the other version. If another tab removed the skin, you can save your work as a copy.

If you have unsaved changes and you select **Cancel**, press `Esc`, use the browser Back button, or open a link, the Studio asks first. You can keep editing, discard the changes, or keep them as a draft.

## Drafts

While you paint, the Studio keeps a draft of your unsaved changes in this browser. The draft does not change the saved skin. Each open editor has its own draft, so two tabs do not overwrite each other.

If you close the tab before you save, the draft stays. The next time you open the Studio, it asks if you want to continue the draft. **Continue** opens the draft. **Discard** deletes it, and the message that follows has an **Undo** button. The Studio does not keep the undo history. Drafts that are still open in another tab do not appear in this list. If a draft has no saved skin anymore, **Save as new skin** adds it to the library and selects it. If the list cannot load, select **Try again**.

If you select **Save draft and close** and the browser cannot save the draft, the editor stays open. It shows the reason and a button to download the PNG, so you do not lose your work.

If your browser blocks site storage or the storage is full, the Studio still works, but it does not keep skins or drafts. Use the download button above the texture to keep your work. In this case, the browser asks before you leave the page with unsaved changes. The browser also asks if you leave before the first draft is kept.

## The library [#your-skins]

The Skin Studio, Upload, and Generator pages share one library in this browser. A skin in the library keeps its original file and its current version, the model for each, and its name.

- The library stays only in this browser on this device. It does not sync to other devices or accounts.
- If you clear the site data, or if the browser removes old site data, the library is deleted. Use **Download PNG** to keep a copy of a skin.
- Select a skin once to use it. Each skin has a menu with **Rename**, **Duplicate**, **Download PNG**, **Revert to original**, and **Remove**. Use the arrow keys to move between skins.
- **Duplicate** adds a copy named "Name copy". A copy of that copy is named "Name copy 2", then "Name copy 3", and so on.
- A dot on a skin means that it has unsaved edits in a draft.
- After you remove a skin, select **Undo** in the message to get it back.
- If the browser cannot save your skins, the library shows **Not saving** with a crossed-out disk. The reason appears below the list.

## Edit from Upload or Generator [#edit-from-upload-or-generator]

The [Upload](/upload) and [Generator](/generator) pages have the same **Edit skin** button and the same editor. When you save, the edited skin is selected, and the page keeps its other choices. The page sends nothing until you select its generate button.

## Privacy

Browsing Gallery downloads its catalog from `cool-skins.skinsrestorer.net` and thumbnails from `textures.minecraft.net`. Selecting a gallery skin downloads its PNG from the texture server. These reads do not upload your local skins.

Editing, the library, drafts, and PNG downloads happen in your browser. The Studio does not send your skin image to SkinsRestorer or to any other server until you select a generate button. Adding, renaming, or removing a skin in the library does not send it either.

If you open a texture URL or a `.skin` file, your browser downloads the texture from `textures.minecraft.net`. The generate button sends the selected PNG to MineSkin. With the **Axolotl** method and a selected cape, it sends the PNG to Axolotl, the SkinsRestorer cape upload service, instead. Read [MineSkin integration](/docs/integrations/mineskin) for more.

## If the 3D model does not show

The 3D model needs WebGL. If your browser turns off WebGL or loses the graphics context, the Studio shows a message instead. Editing the texture, the skin check, generating, and the download still work. In the editor, select **Try again** to start the model again.
