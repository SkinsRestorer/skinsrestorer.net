A cape can be part of the same signed profile property as the skin. A client that receives this property can display both textures.

## Copy a player's equipped cape

1. Find a Minecraft account with the cape equipped.
2. Run `/skin set <playerName>` with that account name.
3. Ask another player to check the skin and cape.

The copied property contains the skin and the equipped cape together. If the source account changes its cape, run `/skin update` to request fresh account data.

## Add a supported cape to an uploaded skin

The website's [Upload](/upload) and [Generator](/generator) pages show cape choices supported by their generation route.

1. Upload your skin PNG.
2. Choose **Axolotl** for its supported capes, or **Official** with a key that grants cape access.
3. Choose a cape from the available list.
4. Generate the command.
5. Apply the command on the server.

The list and service grants can change. If a cape is unavailable, inspect the available list and your API key grants. Do not assume every MineSkin key can generate every cape.

## Limits

- This changes the profile shown on a server. It does not grant a cape to your Microsoft account.
- Arbitrary cape PNG uploads are not supported by these pages.
- Editing signed texture data invalidates its signature.
- Client cape mods can override the server-provided cape.

A selected cape in **Axolotl** mode uses the website's cape-aware proxy route. **Official** mode uses MineSkin with your key.

Read [skin properties and signatures](/docs/concepts/skin-properties) for the technical model, or [upload a PNG](/docs/features/skin-upload) to try it.
