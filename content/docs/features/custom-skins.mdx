A custom skin gives a signed texture a server-owned name, such as `lobby`. Players can then use `/skin set lobby`.

## Before you start

You need console access or `skinsrestorer.admincommand.createcustom`. On a network, create the skin through the proxy that owns skin storage.

## Create from a PNG

1. Open [Generator](/generator).
2. Choose your skin PNG.
3. Enter a short skin name, such as `lobby`.
4. Choose **Classic** or **Slim**.
5. Choose the generation method and select a supported cape if you need one.
6. Select **Generate /sr createcustom command**.
7. Run the generated command in the server or proxy console.

The generator returns a command. It does not download a storage file or install the skin on your server.

## Create from a player name or URL

```text
/sr createcustom lobby xknat
```

For an image URL, keep the URL quoted and specify the model:

```text title="Replace the example URL with a real skin PNG"
/sr createcustom lobby "https://example.com/lobby.png" classic
```

Creating an existing name updates that custom skin. Back up valuable custom skins before replacement.

## Check and reuse

1. Run `/skin set lobby` in game.
2. Check the appearance from another player.
3. Run `/sr info skin lobby` to inspect the stored texture.

Use `lobby` in a [default skin list](/docs/configuration/default-skins) or the [custom menu list](/docs/configuration/skin-menu).

To change the menu label, run `/sr setcustomname lobby Lobby skin`. The command uses the same permission as `createcustom`.

## Existing skin files

The generator's reverse conversion can read supported existing skin storage files. Use it to recover the texture for editing. Do not hand-edit a texture value or signature.

Read [storage and backups](/docs/configuration/backups) before you remove stored data.
